## English

Release {{VERSION}}.

### Fixes

- Docker Compose deployments now use the managed GeoIP directory mode, keeping provider selection and in-place database updates available from **Settings → Monitoring**.
- Existing databases under `/opt/1panel/geo` remain readable when the matching file is not yet present under `/var/lib/thism/geo`; future managed updates continue writing to the new generic directory.
- Manual Compose, Docker, and source-build instructions now prepare a writable GeoIP directory and accurately distinguish managed mode from legacy fixed-path overrides.
- Release and CI agent builds now generate frontend assets before compiling embedded binaries, preventing clean-run failures caused by a missing `frontend/dist` directory.

### Assets

- Signed linux/amd64 and linux/arm64 agent binaries are attached.
- Signature and version sidecar files are attached for each agent binary.
- Container images are published to GHCR as {{VERSION}}, sha-{{SHORT_SHA}}, and latest.

## 中文

发布 {{VERSION}}。

### 修复内容

- Docker Compose 部署改用托管 GeoIP 目录模式，确保仍可在 **设置 → 监控** 中选择数据源并在线更新数据库。
- 当 `/var/lib/thism/geo` 中尚无对应数据库时，继续读取 `/opt/1panel/geo` 下的旧数据库；后续托管更新仍写入新的通用目录。
- 手动 Compose、Docker 和源码构建文档现在会准备可写 GeoIP 目录，并明确区分托管模式与旧版固定路径覆盖模式。
- CI 与 Release 的 agent 构建会先生成前端资源，避免全新检出环境因缺少 `frontend/dist` 而失败。

### 发布产物

- 已附带签名的 linux/amd64 和 linux/arm64 agent 二进制文件。
- 每个 agent 二进制文件都附带对应的签名和版本 sidecar 文件。
- 容器镜像已发布到 GHCR，标签包括 {{VERSION}}、sha-{{SHORT_SHA}} 和 latest。
