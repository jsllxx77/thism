# v0.6.32

## English

Release v0.6.32 — concurrency control-plane remediation.

### Changes

- Added a per-node command stream protocol: server-assigned `command_stream_id`, contiguous per-node sequences, retired watermarks, and a stream/watermark handshake that must complete before the server sends any control command.
- Split the update job target model into two dimensions: server-owned `delivery` (pending → sending → sent / send_failed, with generation and attempt tracking) and agent-owned `execution` (accepted → downloading → verifying → restarting → succeeded / failed / unknown). Execution transitions are monotonic, terminal states are sticky, and only committed states are broadcast.
- Serialized command sends against connection replacement in the Hub: a command is either committed to the current connection generation or fails explicitly; stale connections can no longer submit status, metrics, heartbeats or offline events.
- Added durable cancel tombstones that close assigned sequences without deleting jobs, and an audited operator disposition flow for `unknown` execution states. An undisposed `unknown` blocks the node's control plane until resolved.
- Added database-rollback reconciliation: the server adopts the agent's retired watermark, advances `next_seq` transactionally, never reuses sequences, and records `rollback-reconciled` audit intervals.
- Agents now persist their stream id, retired watermark, in-progress stage and the last 1024 execution records atomically (temp file + fsync + rename). JobID/seq dedup replays exact states, future sequences are rejected with `sequence_gap`, and corrupted local state quarantines the node without resetting the watermark.
- Remote commands and auto-update now share one serialized update executor with mutual exclusion, stage leases (download 2m / verify 1m / restart 2m), cancellable downloads before the rename commit point, and SHA256-based recovery after it. Post-commit failures converge to `succeeded` or `unknown + control-blocked`, never to a clean "did not execute".
- Bounded the shutdown sequence: HTTP server, Hub, dispatcher, metrics retention and rollup workers stop before the store closes, each with deadlines. Slow dashboard subscribers and alert drops no longer block the control plane.
- Bounded update detail retention (180 days / 1024 rows per node) that never silently deletes in-progress or `unknown` records, and closes pruned sequences with retirement records.

### Upgrade note

- The server withholds control commands until the agent completes the stream/watermark handshake. Older agents keep monitoring and auto-updating, but cannot receive new remote update commands. Signed `v0.6.32` agent binaries are attached and auto-update within 30 minutes.

### Assets

- Signed linux/amd64 and linux/arm64 agent binaries are attached.
- Signature and version sidecar files are attached for each agent binary.
- Container images are published to GHCR as v0.6.32, the commit SHA, and latest.

## 中文

发布 v0.6.32 —— 并发控制面整改。

### 更新内容

- 新增每节点命令流协议：服务端分配的 `command_stream_id`、每节点连续序列、已退休水位，以及必须在服务端发送任何控制命令前完成的流/水位握手。
- 更新任务目标拆分为两个维度：服务端所有的 `delivery`（pending → sending → sent / send_failed，带代际和尝试记录）和 Agent 所有的 `execution`（accepted → downloading → verifying → restarting → succeeded / failed / unknown）。执行状态转换单调、终态粘滞，只广播已提交状态。
- Hub 中命令发送与连接替换线性化：命令要么提交给当前连接代际，要么明确失败；stale 连接不能再提交状态、指标、心跳或离线事件。
- 新增持久取消 tombstone，收口已分配序列而不删除任务；`unknown` 执行状态提供带审计的操作员处置流程，未处置前阻断该节点控制面。
- 新增数据库回滚追平：服务端采纳 Agent 水位、事务性提升 `next_seq`、绝不复用序列，并记录 `rollback-reconciled` 审计区间。
- Agent 现在原子持久化 stream id、已退休水位、进行中阶段和最近 1024 条执行记录（临时文件 + fsync + rename）。JobID/seq 去重只回放精确状态，未来序列以 `sequence_gap` 拒绝，本地状态损坏时节点进入隔离且不重置水位。
- 远程命令与自动更新统一走同一个串行更新执行器并互斥：阶段租约（下载 2 分钟 / 验证 1 分钟 / 重启 2 分钟）、Rename 提交点前可取消下载、提交点后按 SHA256 恢复。提交后失败收敛为 `succeeded` 或 `unknown + control-blocked`，绝不会当作“未执行”。
- shutdown 流程有界化：HTTP 服务、Hub、Dispatcher、指标 retention 和 rollup worker 在 Store 关闭前依次停止，全部带超时。慢 dashboard 订阅者和告警丢弃不再阻塞控制面。
- 更新详情有界保留（每节点 180 天 / 1024 条），绝不静默删除进行中或 `unknown` 记录，被清理的序列以 retirement 记录收口。

### 升级说明

- 服务端在 Agent 完成流/水位握手前不会发送控制命令。旧 Agent 可继续监控和自动更新，但无法接收新的远程更新命令。已附带签名的 `v0.6.32` agent 二进制，旧 Agent 会在 30 分钟内自动更新。

### 发布产物

- 已附带签名的 linux/amd64 和 linux/arm64 agent 二进制文件。
- 每个 agent 二进制文件都附带对应的签名和版本 sidecar 文件。
- 容器镜像已发布到 GHCR，标签包括 v0.6.32、提交 SHA 和 latest。
