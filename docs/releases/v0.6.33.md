# v0.6.33

## English

Release v0.6.33 — legacy agent update compatibility fix.

### Changes

- Fixed a deadlock where a server running the v0.6.32 stream/watermark handshake protocol withheld update commands from agents that predate the handshake (or any agent that never completes it). Such jobs stayed `pending` with `delivery_error = "agent handshake pending"` forever and nothing retried them; the only workaround was manually reinstalling the agent.
- Added a handshake grace period (`hub.HandshakeGracePeriod`, 30 seconds): a connection that does not complete the handshake within the grace period is treated as deliverable (fail-open), so legacy agents receive their update commands and can upgrade themselves.
- Each agent connection now schedules a pending-delivery sweep after the grace period, so deliveries are retried even when the handshake-triggered resend can never fire. Sweeps are idempotent: they only deliver sequences beyond the agent's retired watermark.
- New-protocol agents are unaffected: they handshake immediately on connect (well under the grace period), and command delivery stays strictly gated during the grace period.

### Upgrade note

- This is a server-side fix; agents do not need to be reinstalled. After upgrading the server, pending update jobs targeting older agents complete automatically within 30 seconds of the agent's next connection (or immediately when the agent has been connected for more than 30 seconds).

### Assets

- Signed linux/amd64 and linux/arm64 agent binaries are attached.
- Signature and version sidecar files are attached for each agent binary.
- Container images are published to GHCR as v0.6.33, the commit SHA, and latest.

## 中文

发布 v0.6.33 —— 旧版 Agent 更新兼容性修复。

### 更新内容

- 修复死锁：运行 v0.6.32 流/水位握手协议的服务端，会一直扣留更新命令不下发给不支持握手协议的旧版 Agent（或任何始终不完成握手的 Agent）。这类任务永远停留在 `pending`，错误为 `delivery_error = "agent handshake pending"`，且没有任何重试机制；此前唯一解决办法是手动重装 Agent。
- 新增握手宽限期（`hub.HandshakeGracePeriod`，30 秒）：连接在宽限期内未完成握手即视为可投递（fail-open），旧版 Agent 因此能收到更新命令并自行升级。
- 每次 Agent 连接后都会在宽限期结束时触发一次待投递清扫，即使握手触发的补发永远不会发生，投递也会被重试。清扫是幂等的：只投递超过 Agent 已退休水位的序列。
- 新协议 Agent 不受影响：它们在连接后立即完成握手（远小于宽限期），且宽限期内命令投递仍被严格扣留。

### 升级说明

- 这是纯服务端修复，Agent 无需重装。升级服务端后，指向旧版 Agent 的待处理更新任务会在 Agent 下次连接后 30 秒内自动完成（若 Agent 已连接超过 30 秒则立即下发）。

### 发布产物

- 已附带签名的 linux/amd64 和 linux/arm64 agent 二进制文件。
- 每个 agent 二进制文件都附带对应的签名和版本 sidecar 文件。
- 容器镜像已发布到 GHCR，标签包括 v0.6.33、提交 SHA 和 latest。
